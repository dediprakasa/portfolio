I build tools where passing means proof, not self-report.

thesis

Most study tools ask you whether you understood. Mine ask the system. A Kubernetes drill passes when jsonpath and exec-in-pod assertions pass on the cluster, not when a checkbox is ticked. A web exploit passes when the vulnerable code path recorded that it ran. An on-chain flag cannot be read until the contract itself reports solved() == true. The learner cannot talk the tool into a pass, and neither can I.

The same rule applies to my own claims. On 2026-10-28 I re-counted every drill, lesson, action and challenge from each app's live API, re-ran every test suite, and re-checked the on-chain registry with cast. Every drill and challenge is reachable from its curriculum, each placed in exactly one lesson: 60 of 60 CKAD drills, 40 of 40 CKA drills, 24 of 24 web challenges, 20 of 20 contracts. Where a check failed, the number says so instead of being rounded up. The commands are at the bottom so a reader who cares can re-run them.

01ckad-sim kubernetes incident drills, phone-first

A CKAD incident simulator. Each drill applies a broken manifest set into its own namespace on a real k3s node. You investigate and repair it with tap-driven kubectl actions, then ask the app to check. The check is a set of assertions, never a self-report. A timed exam mode scores a random draw of drills per CKAD domain.

On 2026-10-28 that verifier passed 60 of the 60 drills, in two runs on the same day: the 50 drills in the other seven modules in one process, then the 10 base drills in another. The sandbox forces every command into the drill's namespace, rejects -A and cluster-scoped resources, limits kubectl auth to can-i, and gives helm only release and chart-reading subcommands.

05ai-roadmap + portal labs that measure the model, one URL for everything

An AI engineering path where every one of the 22 lessons carries an executable lab that calls a real model and grades the learner on what it measured: unique outputs across identical prompts, pairwise similarity, latency, tokens, retrieval hit rate, injection resistance. The verdict question unlocks only after the required runs, and the answer is graded against the numbers on screen, not the lesson text.

The portal puts one URL and one token in front of all tracks, installable as a PWA. Its reverse proxy drops any client-supplied credentials and injects each upstream app's token server-side from its own token.txt, so the browser never holds a lab token. Tokens travel in the URL fragment, which is never sent to the server, and the one legacy query form is redacted in the access log.

what broke and how I found it

On 2026-10-26 I sent sec-lab, which I had already marked verified, through a cloud multi-agent code review. It came back with 10 verified findings. Four of them:

  1. Exercise progress could regress. Every run overwrote the stored record for a step, so re-running a finished step that then failed flipped it back to not done and dragged the lesson's counters down.
  2. A prose exercise silently disappeared. Once every lesson had an interactive runner, the renderer dropped the written exercise (title, steps, done-when) instead of showing both.
  3. A timeout was not enforced. The runner's executor was used as a context manager, whose exit waits for the stuck job, so the 10 s limit never fired.
  4. The access token was written to the access log. One-tap links carried it in the query string, and uvicorn logs the request line before the page can scrub the address bar.

The same review read the tunnel watchdog. It probed only the public URL, so a local backend blip looked like a dead tunnel: the watchdog rotated a healthy tunnel and the public URL changed for good. The fix probes the local backend first and keeps the tunnel when the app is the one that is down. It is in two of the six tunnel scripts so far; the other four are next.

chain-lab was unpassable. The registry address in deployments.json was not the registry. forge script runs the deploy during its simulation phase, so the file-writing cheatcodes fired, then the broadcast failed on a nonce clash with another process using the same account, leaving files that pointed at contracts that were never deployed. Deploys now use an uncontended account, write pending files, and promote them only after every binding self-checks, 20 of them today.

None of this was caught by reading harder. It was caught by an independent judge script that re-runs every one of the 116 exercise actions through the live API and reports done only when all of them are, and by before/after assertions on every drill: the broken state has to fail every check, and the documented fix has to pass every check. On 2026-10-27 that drill verifier rejected four ckad-sim drills. Three of them, svc-selector, liveness-port and init-blocked, were repaired and re-verified on 2026-10-28. The fourth, pvc-pending, survived the first repair pass: its own documented fix left a cluster-scoped StorageClass behind, so every broken state after the first run bound at once and the drill could not fail. Once the fix was made namespace-scoped and the drill cleaned up the leftover class, it passed too. The same day the 13 extra drills and the four unattached web challenges were mapped into their learning paths, so every drill and challenge is now reachable from a curriculum: 60 of 60 CKAD drills, 40 of 40 CKA drills, 24 of 24 web challenges, 20 of 20 contracts, none duplicated, none orphaned. Today the verifier passes 60 of the 60 ckad-sim drills. Self-report is not a pass.
